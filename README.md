# yadro_impulse_test usage

Запускаем команду 

```
make run_all
```
чтобы скомпилировать и запустить проект, будут по очереди выполняться вычисления файлов, находящихся в директории test_files. 

Так же есть цели: 
>`run` - цель для запуска конкретного файла, но в таком случае придётся в Makefile прописать название интересующего файла. Данная цель сама пересобирает нужные файлы и обновляет статическую библиотеку (obj/csv_read.a) и создает исполняемый файл (bin/csv_read), поэтому вызывать цель build/rebuild не обязательно.

>`run_and_valgrind` - цель для запуска программы с проверкой на Valgrind (после завершения выполнения программы будет сгенерирован файл valgrind.log с результатами проверки), там так же придётся вручную прописать название интересующего файла в Makefile. 

>`debug` - цель для компиляции проекта с отладочной информацией. В ней создается файл bin/debug, который вы можете сами запустить так же с интересующим вас файлом.

## О проекте

В моей реализации происходит два прохода по файлу, во время первого прохода копируются значения в структуру CSVFile_t, а выражения, которые надо будет посчитать, записываются в Formulas_t. После этого происходят вычисления, осуществляется проход только по всем непосчитанным выражениям, если одна формула зависит от другой, то программа будет рекурсивно проходиться по таким ячейкам, пока не наступит момент, когда встретится ячейка, которой для вычисления потребуется два уже известных числа. 

Если две ячейки зависят от одинаковой третьей, то эта третья ячейка посчитается только один раз, в дальнейшем будет использоваться уже посчитанное значение.

## Что можно было ещё поправить

Во многих ошибках у меня пишется в какой колонке и в какой строчке возникла ошибка, но не везде, можно было бы это дописать, если было бы больше времени.

Самая страшная ошибка - бесконечная рекурсия, сечас это никак не обрабатывается и никакой защиты от этого нет, есть только возможные идеи, как это исправить, но опять же недостаточно времени.

Так же я подозреваю, что всетаки я выбрал не самый лучший алгоритм для парсинга. Чтобы была возможность всего лишь два раза пройтись по файлу, пришлось создавать довольно много вспомогательных массивов, в которых у меня хранятся данные так, чтоб к ним можно было более менее быстро обратиться, т.е. я использую довольно много памяти.
